# Planning and Spec Authoring: participant brief

Welcome. This session tests whether our white-paper module is clear and usable.
We are testing the document, not you. Work as you normally would with Claude Code.
You may think aloud as you work; this is optional.

## Your task

> Users want to be able to remove a note they have created. Add a delete option
> to notes.

Use the Planning and Spec Authoring module to prepare a specification for this
ticket in this repository. Stop when you believe it is ready for the Plan
Approved gate. This session covers planning and specification authoring; do not
implement the feature or change application source or tests.

## What to read

- [Planning and Spec Authoring](https://group-19-nbn-sdlc.vercel.app/modules/planning-and-spec-authoring)
- [Plan Approved gate](https://group-19-nbn-sdlc.vercel.app/modules/plan-approved)

Keep these pages available while you work. Follow the module's own instructions
and prompts. These are the two white-paper modules in scope for this session;
use the repository's existing context files and project documentation as needed.

## Your workspace

- Repository: [nbn-usability-planning-spec](https://github.com/Sajad-Ali-Dev/nbn-usability-planning-spec)
- Environment: the prepared Windows VM, with VS Code and Claude Code.
- Application: [http://localhost:3000](http://localhost:3000), when running.

Open Claude Code from this repository's root folder. The facilitator supplies
application test access separately. If something in the environment does not
work, tell the facilitator so it can be fixed outside the task time.

If the module calls for a product-owner decision, ask the facilitator, who acts
as the mock project's product owner. Questions about the module's wording are
also welcome; the facilitator will record them without explaining the intended
answer.

## What to save

Save your specification as `notes-delete-spec.md` in the repository root. Save
any supporting artifacts the module requires with it, either in that document
or in clearly named files linked from it.

Tell the facilitator when you believe the specification is ready for review.
It will go to a separate Gate 1 approver after the session; you do not approve
your own specification. GitHub publication is handled by the study team.

## Session timing

The session lasts 75 minutes: introduction and handoff, up to 45 minutes working
on the task, then a short questionnaire and debrief. The facilitator will tell
you when to begin and when to stop. If you are unfinished at the stop time,
save your current work and describe where you stopped. Unfinished work is a
useful result.

At the end, leave your Claude session available so the facilitator can record
usage information. Do not put passwords, API keys or environment-file values
in the specification or session notes.
